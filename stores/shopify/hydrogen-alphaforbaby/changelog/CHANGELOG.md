## 2026-08-16 09:32 (Asia/Jerusalem) — assistant (owner-authorized): deleted 3 products stuck permanently un-buyable by a Shopify-side indexing bug
**By:** Claude (direct edit, owner-authorized — same no-dev-agent gap as the entry below)
**Context:** A 14-day audit (all 34 active products, cross-referencing this changelog + the `product_images`/`product_videos` write tables + today's `cj_rewrite_all_copy` tool logs) found exactly 3 products where Shopify's Storefront API `encodedVariantAvailability` field (`@inContext(country: US)`, matching this site's actual query in `app/lib/context.js`) was stuck empty (`"v1_"`, version prefix only) despite `encodedVariantExistence` being fully populated and real CJ stock existing — the live PDP showed every size/color "sold out" with Add to Cart disabled, confirmed by fetching the actual rendered HTML at alphaforbaby.com, not just the API response. A trivial no-op `productVariantsBulkUpdate` (re-setting each variant's existing price, meant to force Shopify to reindex) was applied to all 3 and confirmed ineffective after 12 checks over ~6 minutes. No other product in the catalog showed this mismatch.
**Changed:** Deleted all 3 products via Admin API `productDelete` after archiving full data (title, all variant SKUs/CJ variant ids, CJ supplier product id, pricing, image URLs) to `changelog/deleted-products-encodedVariantAvailability-2026-08-16.md` in case we want to re-source the same CJ items fresh later: **Little Chef Play Set** / "Lace-Trimmed Chef Outfit for Babies" (`lace-trimmed-chef-outfit-for-babies`), **Girls Cozy Pajama Set** / "Girls' Breathable Pajama Set" (`girls-breathable-pajama-set`), **Toddler Cozy Fall Set** / "Chic Toddler Fall Set" (`chic-toddler-fall-set`). Verified post-delete on `/collections/all` and checked for orphaned links (homepage, recommendations). Open item for Itzik: this affected 3 of 34 recently-edited products with no clear pattern — worth deciding whether to file a Shopify support ticket so it doesn't quietly recur.

## 2026-08-14 00:42 (Asia/Jerusalem) — assistant (owner-authorized): fixed dead "Sold Out" badge on collection grid pages
**By:** Claude (direct edit, owner-authorized — Sol has no dev tools since the 2026-07-23 charter narrowing, so there was no owning agent to route this to)
**Context:** Owner asked for a code audit of how "Sold Out" / purchasability is determined across the storefront, worried that untracked CJ inventory (`inventoryItem.tracked = false` on every variant, so raw `inventoryQuantity` always reads 0) might be causing false "Sold Out" states. Audit found the PDP, homepage, and cart already correctly gate everything on `availableForSale` — no raw-quantity bug existed there. But a real, different bug turned up: `ProductItem.jsx` computes `available = product.availableForSale ?? true` and renders the "Sold out" badge off that, while neither collection route's GraphQL query (`ProductItem` fragment in `collections.$handle.jsx`, `CollectionItem` fragment in `collections.all.jsx`) ever fetched `availableForSale` on `Product` — so the field was always `undefined` and the `?? true` fallback always won. The sold-out badge on every collection/category grid was permanently dead regardless of real stock.
**Changed:** Added `availableForSale` to the `Product` selection set in both the `ProductItem` fragment (`app/routes/collections.$handle.jsx`) and the `CollectionItem` fragment (`app/routes/collections.all.jsx`), matching the field already correctly fetched in `_index.jsx` and `products.$handle.jsx`. Ran `npm run build` (passed, codegen regenerated `storefrontapi.generated.d.ts` with the new field), deployed to production via `npx shopify hydrogen deploy --force --no-lockfile-check --env-branch main`, and verified live: `/collections/all` and 5 live PDPs all render correctly with no false "Sold Out" state (expected, since every active product currently has real CJ stock — the fix only changes behavior the next time a product actually goes out of stock).
